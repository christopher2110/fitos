How FitOS Skills Work

FitOS skills are Claude-compatible AI agents you import, configure, and own. No closed AI layer. No vendor lock. Your Anthropic key, your agent loop.

What a Skill Is

A skill is a folder with two files. Drop the folder into /skills/. Run npm run skills:scan. Enable in settings. Done.

skills/ └── weekly-checkin-summary/ ├── manifest.json ← skill metadata and routing └── system.md ← instructions Claude follows

Skill Manifest Format

Every skill uses the same structure. All fields are required — the scanner skips folders with missing or malformed manifest.json.

manifest.json
{ "id": "skill-name", // unique identifier, matches folder name "name": "Human-readable Name", "description": "What this skill does (shown in the dashboard)", "version": "1.0.0", "model": "claude-haiku-4-5", // or claude-sonnet-4-5 / claude-opus-4 "inputs": [ { "tab": "CheckIns", "range": "CheckIns!A1:J200" } ], "outputs": [ { "tab": "Activity", "action": "append" } // append | prepend | overwrite ], "requires_tools": [] // list tool names if needed }
system.md
You are a fitness coaching assistant working with {coach_name}. When {client_name} submits their weekly check-in, analyse their responses and return a structured summary the coach can act on immediately. ## Output Format - Compliance score (0–100) - Top 3 wins — specific, from the client's own words - Single coaching priority - Suggested reply message Be specific. Reference actual data. Flag anything that looks like a red flag.

Example: weekly-checkin-summary

The built-in summary skill runs every time you click Run in settings. It reads 7 days of check-in data, scores the week, surfaces coaching priorities, and drafts a reply — in under 3 seconds.

View full weekly-checkin-summary skill files
manifest.json
{ "id": "weekly-checkin-summary", "name": "Weekly Check-in Summary", "description": "Reads the last 7 days of check-in data and writes a coaching summary to the Activity feed.", "version": "1.0.0", "model": "claude-haiku-4-5", "inputs": [ { "tab": "CheckIns", "range": "CheckIns!A1:J200" }, { "tab": "Profile", "range": "Profile!A2:D50" } ], "outputs": [ { "tab": "Activity", "action": "append" } ], "requires_tools": [] }
system.md
You are a fitness coaching assistant. Your job is to read a client's check-in responses and produce a concise, actionable coaching summary. ## Data You will receive rows from the CheckIns tab. Each row contains: - Date, workouts completed vs planned, nutrition rating (1-10), sleep hours, sleep quality (1-10), energy (1-10), mood (1-10), bodyweight, client notes. ## Output Format Write to the Activity tab in this format: ### Weekly Summary — [date range] **Compliance score:** [0-100] **Top wins:** [3 specific wins from the client's own language] **Priority this week:** [single most important coaching focus] **Suggested reply:** [2-3 sentences the coach can send or edit] ## Rules - Be specific. Reference actual numbers and the client's exact words. - Flag anything unusual: injury language, burnout signals, >5% bodyweight change. - Tone: warm and precise. Coaches are time-pressed.

How to Import a Skill

1
Copy the skill folder into /skills/
Each skill is a self-contained folder with manifest.json + system.md. No other files required (unless the skill uses tools.json).
2
Run npm run skills:scan
Validates the manifest, checks for required fields, and registers the skill with the dashboard. Exits with an error if the manifest is malformed so you catch it before deploy.
3
Enable in Agent Settings
Open /settings/agents, find your skill in the list, and toggle it on. Skills hot-load on the next run — no server restart required.
Terminal
# 1. Drop the skill folder in $ cp -r ~/my-skill skills/ # 2. Validate + register $ npm run skills:scan # 3. Enable in /settings/agents — then run it from the dashboard

Why BYOK

Your Anthropic key is stored encrypted in your own Google Sheet (AES-256-GCM). FitOS never sees it in plaintext. Here's what that means:

You pay Anthropic directly
No markup. No platform surcharge. A weekly check-in summary costs fractions of a cent — and that goes to Anthropic, not FitOS.
Your limits, your caps
Set rate limits and spend caps in your Anthropic console. FitOS reads your key at run time and has no control over your quotas.
Portable
Your key is in your environment. Migrate away from FitOS and your AI agents come with you. No lock-in.
Open stack
Every other coaching platform routes clients through a closed AI layer. FitOS doesn't. You own the agent loop end-to-end.

Import from Claude Code

Any skill built for Claude Code can be adapted for FitOS with minimal changes. The agent loop is compatible — only the metadata format differs:

1
Rename SKILL.md → system.md
The instructions file is identical in purpose. Just rename it.
2
Add a manifest.json
Claude Code uses YAML frontmatter in SKILL.md. FitOS uses a separate JSON file. Copy the name, description, and version fields, then add id, model, inputs, and outputs to declare what tabs the skill reads and writes.
3
Run npm run skills:scan
Validates the manifest and registers the skill. You're done.
